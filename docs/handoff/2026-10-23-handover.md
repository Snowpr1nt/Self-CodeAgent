### 2.1 Git 所有权保护与安全用法

工具运行账户和 `.git` 所属账户可能不同，直接运行 Git 会出现 `detected dubious ownership`。使用每条命令仅信任本项目的方式即可，不需要全局 `safe.directory=*`：

```powershell
$projectRoot = 'C:/Users/Snowprint/OneDrive/工作/PersonalProject/MewCode'
Set-Location -LiteralPath $projectRoot
git -c "safe.directory=$projectRoot" status --short --branch
git -c "safe.directory=$projectRoot" diff --check
git -c "safe.directory=$projectRoot" log -12 --oneline
git -c "safe.directory=$projectRoot" remote -v
```

不必再用正则替换 Windows 路径分隔符；曾有一次 `-replace` 转义错误导致只读命令失败，直接使用上述固定正斜线路径更稳妥。

在当前平台，写 `.git` 可能需要工具层权限提升；这是宿主权限要求。用户已授权每日开发和可回退提交，不需要额外进行一轮对话确认。继续遵守实际工具审批结果。

## 7. 交付标准与协作方式

- 中文沟通，先讲用户价值，再给必要技术解释；用户希望既得到可运行代码，也学会开发方法。
- 每个工作单元先定位调用链，写出关键行为的失败测试，再作最小修复。延续现有风格，避免无关大重构。
- 测试结论必须有实际命令和输出支持，区分失败、跳过、排除、环境错误和中断。
- 根据风险运行必要门禁；已充分验证后推进交付，避免没有新理由的重复测试。
- 更新架构/主题文档、测试账本、每日学习日志与路线图，并审阅完整 Diff，包括未跟踪文件。
- Git commit message 用英文，变量遵循 snake_case。未得到新的明确授权时不发布、推送或合并主分支。
- 继续工作的授权已经存在；仅在缺少必要信息、凭据或平台权限确实阻断时说明原因，避免反复要求用户确认同一范围。
- 不删除现有未提交成果，不 reset、不整体清理 `.mewcode/`，不泄露凭据。
- 长任务及时给出简短进度，重点说明已验证事实和下一步要解决的风险。
- 最终交付说明必须包含改动、测试证据、可回退提交和仍存在的限制；引用本地文件时使用可点击绝对路径。
