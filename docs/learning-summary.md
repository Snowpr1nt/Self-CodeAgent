# 14 天学习总结

这条路线把 Code Agent 分成五个可理解的层次：入口与 Provider、Conversation 与 Agent Loop、工具与权限、上下文与长期状态、SubAgent/Worktree/Teams 协作。最重要的认识是：模型只提出下一步，可靠性来自 Python 调用链、数据边界和测试证据。

Day 1–4 建立 Python/uv/Git 基线、模型适配与工具协议；Day 5–8 把多轮循环、权限、MCP、压缩和 Recovery 接成闭环；Day 9–14 继续解决重启记忆、可配置命令、Hook、后台任务、Git 隔离和团队协作。每一天在 `docs/learning-log/day-XX.md` 留下问题、RED/GREEN 与限制，方便回看判断是怎样改变的。

三次有代表性的判断修正：Day 9 发现旧会话共用目录清理会波及新会话，靠真实磁盘测试而不是 Mock 才复现；Day 11 把 Windows `KeyboardInterrupt` 初误判为临时目录问题，最后由禁止 `os.kill(pid, 0)` 的测试定位到控制台事件；Day 13 发现“当前工作树没有新提交”不能证明原分支无未保存成果，因为工作树可能已切换分支。它们共同说明：先观察实际副作用，再决定修复点。

今后增加项目能力时，建议沿用一个循环：界定用户价值和数据保护要求，定位实际入口，写能失败的行为测试，最小实现，运行邻接与全量门禁，审阅 Diff，只暂存目标文件，写下验证证据和剩余限制。Fake/Mock 适合稳定测试协议；涉及文件、进程、Git 的行为必须至少有一条真实本地集成测试。真实在线服务和其它平台仍需要独立 Smoke。
