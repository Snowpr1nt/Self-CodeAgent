# Context 与 Recovery

## 1. 用户价值

长时间运行的 Code Agent 会持续累积消息、工具结果和文件内容。MewCode 用两层机制控制上下文：大型工具输出先落盘，整个会话接近模型窗口上限时再生成摘要，同时保留最近原文和可恢复状态。

```text
Conversation
  -> Layer 1: Tool Result Budget
     -> 大结果写入 .mewcode/session/tool-results
     -> 对话中保留路径与前 2KB 预览
  -> Layer 2: Auto Compact
     -> 摘要较早前缀
     -> 原样保留最近消息和工具调用配对
     -> 附加最近文件、Skill 和可用工具提示
     -> 记录 compact_boundary
```

Day 8 只加固运行中的压缩和恢复边界。进程重启后的 Session 与长期 Memory 注入属于 Day 9。

## 2. Layer 1：大型工具结果落盘

单条工具结果超过 50,000 字符，或同一条消息中的工具结果合计超过 200,000 字符时，完整内容写入会话落盘目录；模型只接收带路径的预览。`ContentReplacementState` 冻结第一次预算决策，避免同一历史在不同轮次产生不同 Prompt。

工具调用 ID 来自外部模型，不能直接作为文件路径。安全的 ASCII ID 保留可读文件名；包含路径分隔符、过长或其他不安全字符的 ID 改用 SHA-256 摘要文件名，确保结果始终位于落盘目录内。

判断 ReadFile 是否正在读取落盘目录时必须使用真实路径边界，不能用字符串 `startswith`。例如 `tool-results-copy` 与 `tool-results` 具有相同前缀，但不是其子目录。

## 3. Layer 2：自动压缩

压缩阈值由模型 context window、20K 摘要输出预留和安全边距共同决定：

- 软阈值：窗口减 20K，再减 13K；受熔断器保护。
- 硬阈值：窗口减 20K，再减 3K；强制尝试压缩。
- 最近原文：至少保留 5 条消息或约 10K tokens，最多约 40K tokens。

摘要只覆盖较早前缀，最近消息逐字保留；若边界落在 `tool_use` 与 `tool_result` 之间，会向前移动，避免产生孤立工具结果。

摘要流只有收到 `StreamEnd` 且存在文本时才算成功。若连接正常返回却提前结束，系统从原始 Conversation 自动重试，最多三次；三次仍未完成时返回明确原因并记录一次熔断失败，不会用半截摘要破坏原历史。

## 4. 落盘文件与压缩边界

压缩前，最近尾部可能已经包含指向落盘文件的预览。压缩成功后不能清空整个落盘目录，否则保留下来的消息和持久化 `compact_boundary` 会指向不存在的文件。

Day 8 将清理改为选择性回收：

1. 从保留尾部收集仍带 `<persisted-output>` 的工具调用 ID。
2. 使用同一安全文件名算法计算需要保留的文件。
3. 删除不再被引用的旧文件和旧替换日志。
4. 保留近期消息仍引用的完整工具输出。

## 5. 中断恢复

替换决策采用 JSONL 追加记录。进程可能恰好在写入一行时被终止，因此加载器逐行校验，并跳过截断、缺字段或类型错误的记录；此前完整写入的记录仍可恢复。

开发命令采用相同原则：安全且幂等的测试命令失败后可自动重跑；Git 写入等非幂等操作必须先检查状态。权限拒绝、沙箱 ACL、确定性断言失败或破坏性风险不能盲目循环重试，必须报告具体原因。

## 6. Day 8 验证矩阵

Fake 场景覆盖：

- 恶意工具调用 ID 无法逃逸落盘目录。
- Unicode ID 和 Windows 保留设备名使用可移植的摘要文件名。
- 相似路径前缀不会被误判为落盘文件回读。
- 截断 JSONL 尾记录不会阻断已有决策恢复。
- 中断的摘要流会自动重试并使用完整摘要。
- 压缩后仍保留近期消息引用的完整落盘输出。
