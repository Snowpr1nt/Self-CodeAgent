# Day 1：建立可复现开发基线

## 今日目标

在不修改业务行为的前提下，把下载源码转换为可回退、可安装、可测试、可解释的工程基线。

## 完成事项

- 初始化 Git 仓库，默认分支为 `main`。
- 原样提交 192 个下载文件，提交为 `fc0b37c`。
- 创建标签 `baseline/python-v0.2.0`。
- 创建 Day 1 工作分支 `docs/day-01-baseline`。
- 安装 uv 0.12.1。
- 使用 `uv sync --locked` 创建 `.venv` 并安装 55 个锁定包。
- 运行全量 pytest，得到 566 passed、3 failed、2 skipped。
- 建立架构图、测试策略和 14 天路线图。

## 重要决策

### 1. 先提交原始压缩包，再添加学习文档

这样可以随时比较“官方下载源码”和后续学习改动。即使后续实验失败，也能回到明确的起点。

### 2. 强制纳入 `.mewcode` 示例文件

原始 `.gitignore` 忽略整个 `.mewcode/`，但下载包在其中包含配置示例和多个 Skill 示例。首次提交使用强制暂存保存这些原始材料，没有修改其内容。

### 3. 使用锁文件而不是 pip 最新版本

之前的快速审阅曾使用临时 pip 环境。Day 1 改为 `uv sync --locked`，保证后续所有人的依赖版本一致，测试结果才可比较。

### 4. 不在 Day 1 修复红色测试

基线的意义是记录真实状态。立即修复会混淆“下载时已存在的问题”和“我们引入的问题”。三个失败已分类，并安排在 Day 11 用 TDD 修复。

## 遇到的问题与根因

### Git dubious ownership

工作区属于 Windows 用户 `Snowprint`，工具命令运行在隔离账户下。Git 的所有权保护因此拒绝操作。解决方式是在每次 Git 命令中仅将当前仓库声明为安全目录，不修改全局 `safe.directory`。

### uv 缓存权限

沙箱不能创建用户级 uv 缓存。经授权后使用真实用户缓存完成同步，项目产物仍只写入被忽略的 `.venv/`。

### pytest 临时目录影响指令发现

如果 `tmp_path` 位于项目 Git 根目录内部，`load_instructions()` 会发现项目的 `MEWCODE.md`，导致隔离测试失真。最终基线把 pytest 临时目录放在仓库外。

## 今日技术理解

- Coding Agent 的核心不是聊天 UI，而是“模型事件 → 工具治理 → 工具结果 → 下一轮模型”的循环。
- 可复现环境和基线提交是 Agent 项目级开发的第一道安全网。
- 测试失败需要先区分源码缺陷、平台差异和测试环境污染。
- 安全功能必须覆盖每一条执行路径；只在后台路径调用 Hook 并不等于系统支持 Hook。
