# Day 4：Tool 抽象与六个核心工具

## 今日目标

理解模型工具调用如何经过注册表、参数校验和本地执行，并用 TDD 加固文件一致性与 Bash 退出码语义。

## 完成事项

- 创建独立分支 `feature/day-04-core-tools`。
- 审阅 Tool 基类、注册表、六个核心工具、Diff 和两级文件缓存。
- 新增工具契约测试，覆盖 Provider Schema、类别和并发属性。
- 补齐读前写保护、缓存新鲜度、Glob/Grep 过滤和 Bash 退出码测试。
- 修复空 `FileCache` 无法首次填充的问题。
- 修复内容变化但时间戳相同仍可被覆盖的问题。
- 修复普通非零 Bash 退出码没有标记错误的问题。

## TDD 记录

### 循环一：文件状态不能只信时间戳

- **RED**：缓存内容为 `before`、磁盘内容为 `after!` 且时间戳相同时，旧实现返回可写。
- **GREEN**：`FileStateCache.check()` 同时比较修改时间与 UTF-8 内容。
- **价值**：避免外部程序恢复时间戳后，Agent 静默覆盖用户改动。

### 循环二：空缓存也是有效依赖

- **RED**：首次 `ReadFile` 后 `FileCache` 仍为空；手工放入旧内容后再次读取会返回陈旧数据。
- **GREEN**：可选缓存统一用 `is not None` 判断；命中内容缓存时先用状态快照验证新鲜度。
- **价值**：区分“没有注入缓存”和“注入了一个当前为空的缓存”。

### 循环三：退出码是协议，不只是数字

- **RED**：普通命令退出 7 时 `ToolResult.is_error` 仍为假。
- **GREEN**：执行结果复用 `_interpret_exit_code()`；`grep` 等命令的退出 1 继续保留为正常业务结果。
- **价值**：Agent 可以基于真实失败调整计划，同时不会误判“没有匹配”。

## 今日技术理解

- Tool Schema 是模型与执行器的 API 合约，Pydantic 模型同时承担文档和运行时校验。
- `category` 决定权限策略，`is_concurrency_safe` 决定调度策略，两者不是展示元数据。
- 读前写不是流程建议，而是乐观并发控制：读取建立版本，写入验证版本。
- 缓存对象的真假值可能被 `__len__` 改写；可选依赖判断应使用身份语义。
- Shell 退出码必须结合命令协议解释，不能统一视为成功或失败。
- 跨平台单元测试应 Fake 进程边界，而不是依赖本机存在某条 Unix 命令。
