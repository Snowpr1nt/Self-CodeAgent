# Day 8：Context 与 Recovery

## 今日目标

理解上下文预算、工具结果落盘、自动压缩、压缩边界和恢复附件的完整链路，并保证安全中断不会把半成品状态当作成功。

## 方案选择

- **仅补测试**：能形成学习样例，但会保留已证实的数据丢失和路径问题。
- **聚焦加固（采用）**：保持现有模块边界，只修复落盘、压缩和恢复的关键不变量。
- **拆分 ContextManager**：长期可维护性更好，但会把 Day 8 扩大为结构重构，风险和工作量不均衡。

Session 重启和长期 Memory 注入明确留到 Day 9。

## 实现要点

- 不可信工具调用 ID 使用受限可读文件名或 SHA-256 摘要文件名。
- 路径包含关系使用解析后的 `Path.is_relative_to()`。
- JSONL 加载按行容错，保留此前完整记录。
- 摘要流必须有结束事件和非空文本，中断时最多自动重试三次。
- 压缩清理只删除不再被近期尾部引用的落盘文件。

## 今日技术理解

- 上下文治理不是单次摘要，而是“结果预算 + 摘要 + 最近原文 + 恢复附件 + 持久化边界”的组合协议。
- 写入路径和目录包含判断都是安全边界，不能信任模型产生的 ID，也不能比较字符串前缀。
- 流式 API 正常结束需要显式终止事件；迭代器自然返回不等于业务完成。
- 清理属于状态迁移的一部分，必须保留新状态仍引用的外部资源。
- JSONL 的价值在于局部恢复；读取器必须允许最后一行因进程中断而损坏。
