# Day 13：Git Worktree

## 今日目标

让隔离任务的实际读写发生在 Worktree，并确保恢复、清理和失败处理不会丢失用户文件或本地提交。验收只在专用临时 Git 仓库执行，开发仓库的 Git 写操作由主代理统一管理。

## 设计判断

保留现有 WorktreeManager、Session 与工具边界，修复可复现的状态和数据保护问题。没有改用进程级 `os.chdir()`：一个进程可同时运行多个 Agent，全局切换目录会让其它任务受影响。

进入后同步的是执行目录、文件工具、Bash 和路径权限；同一对话的转录、工具结果、长期 Memory 与 FileHistory 备份继续归属于原会话。文件历史记录实际编辑目标的绝对路径，避免同名文件混淆。

## TDD 证据

原有 Worktree 测试得到 **50 passed**。随后新增 `tests/test_worktree_safety.py`，按真实 Git 行为逐轮复现：

| 阶段 | RED 结果 | 失败说明 |
|---|---|---|
| 第一轮安全边界 | 9 failed、8 passed | 删除失败吞掉；恢复丢失基线；`-B` 重置分支；查询失败判干净；陈旧清理虚报数量；退出其它目录清掉当前会话 |
| 命令与工具入口 | 4 failed、1 passed | 相对写入落主目录；工具/恢复缺少 Agent 绑定；空基线被 Git 解释为 `HEAD..HEAD` |
| 会话生命周期 | 4 failed | 自动清理当前会话；重复进入丢失原会话；转录根与 Recovery 读路径错误 |
| 用户数据与部分失败 | 2 failed | `.env` 被普通 status 隐藏后遭清理；目录删除而分支删除失败时 Agent 留在不存在目录 |

测试没有伪造 Git 成功响应。删除失败通过真正的 `git worktree lock` 复现；部分成功通过分支引用锁复现；未推送检测使用本地 bare remote，确认没有 upstream 的分支仍被保护。

第一轮最小修复后 Worktree 测试得到 **67 passed**；入口及相邻工具回归曾得到 **90 passed**。继续补齐上述生命周期与用户数据保护后，联合门禁为 **152 passed in 17.59s，退出码 0**。独立审阅再追加三项失败测试：切换检出分支后原分支提交可能被强制删除、自定义 base 误用原仓库 HEAD、Bash OS 沙箱缺少 Git 共享元数据写权限。宿主取得 **3 failed、28 deselected** 的 RED，修复后 **3 passed、28 deselected**；最终联合门禁更新为 **155 passed in 20.85s，退出码 0**。

## 实现要点

- 新建使用 `-b`，保留已有分支；恢复保留独立创建基线，无法确认基线时拒绝默认清理。
- Git 查询非零退出码不能当作无变化；状态检查包含忽略文件。
- 删除检查返回码和磁盘结果；失败不虚报完成，目录已删除时也不会留下失效的执行目录。
- 集中绑定器同步 Agent、六个核心工具、路径权限和 Bash 沙箱配置，退出后恢复原策略。
- 五个核心文件工具新增实例级 `work_dir`；Write/Edit 以解析后的目标记录 FileHistory。
- 当前会话不会被自动清理，重复进入其它 Worktree 不覆盖原退出位置。
- 主代理负责 `agent.py` 的固定会话根与 Recovery 相对路径修复；本日测试同时覆盖这些跨模块边界。
- 删除前核对当前检出分支，避免切换分支后强制删除原分支提交；ExitWorktree 比较真实创建基线；Bash 沙箱只加入已验证归属的 Git 元数据写路径。

## 验证与命令恢复

最终命令覆盖 `test_worktree.py`、`test_worktree_safety.py`、`test_tools.py`、`test_edit_file.py`、`test_permission_boundaries.py`、`test_session_recovery.py` 和 `test_commands.py`，没有跳过或排除测试。

默认执行曾多次在 pytest 临时目录访问和结束清理阶段得到 `PermissionError: WinError 5`，退出码 1，不能计作产品失败或成功。确认进程结束后，使用新的独立临时目录和工具允许的执行权限幂等重跑，最终得到上述绿色结果。没有全局放宽 Git 信任，也没有递归清理开发目录。

## 学到的关键点

1. “已经切换目录”的成功文案不足以证明隔离，必须断言实际文件位置、Bash cwd 和权限根。
2. 当前 HEAD 是结果，创建基线是比较依据；恢复时混用它们会让本地提交失去保护。
3. 清理中的“未知”应该导致保留。被忽略的配置文件仍然是用户数据。
4. 外部命令成功、目录消失、分支删除、内存记录和持久化会话属于同一状态迁移，需要逐一核对。
5. 路径策略与执行工具应采用同一目录解释，否则权限检查通过的路径和实际写入目标可能不同。
